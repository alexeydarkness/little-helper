# Little Helper · API спринта 5

Все запросы ниже требуют `Authorization: Bearer <токен>`. Токен возвращается при регистрации или входе. В ошибках проверки данных и бизнес-правил сервер возвращает `{"message":"..."}`. Ответ 401 может быть без тела.

## Поиск пользователей · экран #27, сервер #28

Экран открывается из меню расписания. Репетитор ищет учеников, ученик ищет репетиторов.

`GET /api/v1/users/search?q=Анна`

- Параметр `q` кодируется как URL. После удаления внешних пробелов и необязательного знака `@` в начале в строке должно быть 2–100 символов.
- Сервер определяет роль по текущему пользователю. Поиск возвращает только пользователей противоположной роли, независимо от регистра в имени и никнейме. Совпадение по подстроке, символы `%` и `_` имеют обычное значение.
- Возвращается до 20 результатов, отсортированных по имени и ID. Пустая выдача — `200 OK` с `[]`. Некорректный запрос — `400`.
- В результате достаточно ID, имени, никнейма и роли. Телефон, email, баланс и аватар в поисковую выдачу не входят.

```json
[
  {"id":7,"fullName":"Анна Петрова","username":"anna","role":"TUTOR"}
]
```

До реализации #28 приложение покажет «Поиск пока недоступен», если сервер ответит 404. Отправка заявок и привязка пользователей относятся к отдельному сценарию.

## Магазин · экран #29, сервер #30

`GET /api/v1/shop` возвращает баланс текущего пользователя и упорядоченный каталог. Клиент показывает цену из ответа и по полю `owned` определяет, доступна ли покупка. `type` принимает `FRAME` или `BACKGROUND`. Стандартные рамка и фон доступны всем сразу, с нулевой ценой.

```json
{
  "balance": 1100,
  "items": [
    {"id":"frame_default","name":"Стандартная рамка","description":"Обычная круглая рамка","type":"FRAME","price":0,"owned":true},
    {"id":"frame_gold","name":"Золотая рамка","description":"Золотая рамка для аватара","type":"FRAME","price":500,"owned":false}
  ]
}
```

Пример показывает первые две позиции. Полный список возвращает сервер.

`POST /api/v1/shop/purchases` принимает JSON с ID из каталога.

```json
{"itemId":"frame_gold"}
```

Успешный ответ `200` содержит новый баланс. Клиент может сразу отметить товар купленным и обновить баланс или перечитать каталог.

```json
{"itemId":"frame_gold","balance":600,"alreadyOwned":false}
```

Повторный запрос для купленного или стандартного товара вернёт `200` и `alreadyOwned: true`. Монеты при этом не списываются. Если монет не хватает, сервер вернёт `409` и сообщение «Недостаточно монет». Для неизвестного товара вернётся `404`, для пустого ID — `400`. Цена и покупатель определяются сервером. Покупки используют только игровые монеты.

Выбор активного оформления и начисление монет за занятия остаются отдельными сценариями. У новых аккаунтов баланс равен нулю.

### Как проверить на локальной PostgreSQL в Docker

Пересоберите сервер (`docker compose up --build -d`), затем зарегистрируйте отдельного ученика для демонстрации. Для проверки платной покупки можно задать ему тестовый баланс в локальной базе. Замените адрес на email своего тестового ученика.

```powershell
docker compose exec postgres psql -U littlehelper -d littlehelper -c "UPDATE users SET balance = 1100 WHERE email = 'shop-demo@example.com' AND role = 'STUDENT' AND balance = 0;"
```

Начисление этим запросом нужно только для локальной демонстрации. Для собственного API-клиента возьмите JWT из `POST /api/v1/auth/login`; цена покупки и остаток видны в ответах API. В профиле остаток обновится после повторного открытия экрана.
